## Document Structure & Standards

Each progress report adheres to the standardized 3-page executive format:

1. **Project Identification & Metadata:**
   - Course, evaluating group roster, repository links, target group roster, primary database engine details, and restored test database targets.
2. **Technical Activity Synthesis:**
   - **Activity 4 (Access Control & Roles):** Access-control plan, threat modeling, RBAC hierarchy (`NOLOGIN` groups vs `LOGIN` accounts), least-privilege boundary enforcement, admin testing, public testing, cross-database connection testing, setup issue resolutions, and constructive owner feedback.
   - **Activity 5 (Maintenance & Monitoring):** Database health inspection, disk footprint and table storage breakdowns, connection/session metrics, bloat and dead tuple analysis, log audit, routine maintenance (`ANALYZE`, `VACUUM`), `EXPLAIN (ANALYZE, BUFFERS)` query performance analysis, and prioritized indexing recommendations.
   - **Activity 6 (Backup, Restoration & Disaster Recovery):** Disaster recovery architecture, RPO/RTO objectives, retention policies, compressed custom format backup (`pg_dump -Fc`), SHA-256 cryptographic verification, archive TOC inspection, complete test database restoration drill, post-restore verification suite, controlled disaster recovery simulation, and production deployment recommendations.
3. **Class Google Sheets Tracker Entry:**
   - Official tabular fields synchronized with course evaluation requirements.
4. **AI Usage Declaration:**
   - Formalized disclosure of AI assistance in schema analysis and verification testing.
